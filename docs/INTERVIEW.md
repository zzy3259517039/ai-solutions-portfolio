# 面试讲解与现场验证

## 三分钟介绍参考

我有电商业务与客户沟通背景，正在向 AI 实施和解决方案方向发展。我用 Codex 等工具辅助实现项目，关注需求怎么拆、哪些数据能相信、怎么验收、失败后怎么处理。我的编程与独立排障能力仍在学习，不把 AI 生成的全部代码说成自己已经完全掌握。

第一项是景区知识库客服。场景是游客反复问票价、退改和交通。资料放在知识库，通过检索节点传给模型，回答保留引用。历史云端测试覆盖 20 道题，包括 1.2 米／1.5 米边界、退票 16:00 的条件、未知实时信息、提示词攻击和票价更新。有一次金额更新正确，但正文仍引用旧版本，项目记录了原因和修正。我会区分草稿预览、公开版本和当前验证结果。

第二项是会议交付 Skill。它把原文整理成纪要、任务 CSV 和待确认事项。核心要求是提议不能变成决策，负责人和日期不能猜，证据必须能在原文找到。脚本可以检查数据结构、日期和原文片段，处理 CSV 公式起始字符，每次生成独立目录。这些检查无法自动证明语义完全正确，最后仍需人工审核。

第三项是更新通知工具。它用 SQLite 保存第一次读到的历史基准和之后发现的新视频，避免重启后重复通知。明确失败按退避重试；超时或进程退出可能意味着已经发出，因此保留 uncertain，先核实再决定是否重发。通知接口受理与手机实际收到分开记录。

团购演示和微信实验室补充展示业务闭环与接口集成。真实支付、POI 权限和客户收费都还没有完成验收，我会明确说明。

## 现场建议演示顺序

1. 从景区原始资料找到某条票务／退改规则，解释检索、上下文、来源三者的关系；云端不可用时使用历史测试材料，不表演假调用。
2. 导出会议参考样例，打开 CSV；再改成不存在的 evidence，展示导出被拒绝。明确此演示验证导出器，模型语义另评估。
3. 用 B 站隔离测试说明重启去重、明确失败和 uncertain 的区别，避免现场依赖真实外部接口。
4. 浏览器完成水果模拟购买、出券、核销，再试一次重复核销。

## 需要自己能讲清楚的追问

| 追问 | 应该能解释的重点 |
| --- | --- |
| 为什么使用 RAG？ | 资料变化时更新知识库；模型须获得召回的依据，避免硬编码答案；检索和生成分别排查 |
| 如何知道答对了？ | 题目、期望、原始结果、来源与边界；固定题 20/20 不能说明覆盖所有游客问题 |
| evidence 校验能证明什么？ | 文本确实出现；无法证明任务、负责人或语义归因正确 |
| HTTP 200 是否代表退款成功？ | 请求受理与业务状态不同，检查可信服务端结果和业务数据 |
| 超时为什么不立即重发？ | 首次请求可能已被接受，盲目重发可能造成重复通知 |
| 支付成功为什么不能相信前端？ | 服务端验签、解密、金额和身份核对，再原子更新；本项目真实支付未验收 |
| 哪些是你独立完成的？ | 按实际参与说明需求、业务规则、操作与验收；不把工具生成、别人代码或指导下完成当成独立掌握 |
