# 微信 POI 接入实验室：接口与交易原型

单商家自有小程序与自有支付的学习原型，包含 Node.js／TypeScript API、MySQL、管理界面、原生微信小程序及部署示例。用于展示业务接口、可信服务端与第三方集成的实现思路。

**真实微信账号、支付、门店 POI、位置权限和视频号全链路未完成验收。** 本地实现不表示平台资格获批、真实资金已流转或商业系统可上线。

## 核心模块

- 微信登录：服务端用 code 换 OpenID，不把 `session_key` 返回小程序。
- 商品与订单：金额为整数分，服务端算价、预留库存和处理超时。
- 支付：APIv3 签名、小程序支付参数、回调验签和解密、身份与金额核对、查单补偿。
- 券与核销：每份商品出券，券号与二维码令牌分开，防重复核销，撤销留痕。
- 退款：申请与最终退款状态分开，结果由回调／查单确认。
- POI 实验记录：人工记录权限、审核、路径和证据，`DONE` 不是微信官方验收。

## 先运行无需数据库的检查

需要 Node.js 22+，在本项目目录执行：

```bash
npm ci
npm test
npm run build
```

单元测试模拟微信请求，并在内存中生成测试密钥，不请求真实微信支付。本次作品集复核不使用原项目 `.env` 或真实数据库。

## 本机完整环境（可选）

另需 MySQL 8，在新的隔离演示环境内执行：

1. 阅读 `.env.example` 与 `scripts/prepare-local-db.mjs`，运行 `npm run db:prepare-local` 生成仅在本机的配置与 SQL。
2. 用自己的 MySQL 管理连接检查并执行 `.local/setup-db.sql`；配置数据库权限后运行 `npm run db:migrate`。
3. 分别启动 `npm run dev:api` 与 `npm run dev:admin`。后台 `http://127.0.0.1:5173/`，API `http://127.0.0.1:3000`。
4. `/api/health` 只说明服务启动；`/api/ready` 的数据库状态用于检查数据库连接。后台密码来自自己的 `.env`。
5. `npm run verify:local` 含数据库集成测试，会写入并清理合成数据；只能在隔离且满足空商家前置条件的实验数据库内运行。不要对生产库或已有商家库运行。

准备脚本在已有 `.env` 或 SQL 时拒绝覆盖。数据库、密钥、截图和配置不随仓库发布。

## 演示与真实交付的边界

服务端收到可信微信结果后才改业务状态，不能仅凭前端“支付成功”或 HTTP 200 出券。原型已有相关核对、幂等和异常分支代码；真实回调及网络异常仍需平台环境实测。

真实接入需要商家主体、小程序资质、商户绑定、合法 HTTPS 域名、支付密钥和 POI 权限。不能猜测平台入口或为验收而随意发起支付。本仓库整理未进行账号配置、付款、退款或云部署。

当前后台共用管理员密码与操作人标记；正式多店员交付需要独立身份、门店授权与进一步安全评估。`deploy/` 是示例配置，必须替换域名、路径并验收。
