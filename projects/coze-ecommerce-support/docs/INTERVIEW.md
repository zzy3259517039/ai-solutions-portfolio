# 简历与面试讲解

## 简历描述参考

> 使用 Coze 与 AI 辅助开发工具实践电商客服辅助原型，设计四类咨询分流及 intent/reply/need_human 输出，结合模拟商品资料查询与退款投诉转人工规则；核查历史运行样例，并整理售后知识库来源缺失问题的分块与标题传递修复过程。

按本人实际参与采用。两个模块独立存在，完整集成、原始云端回归记录与真实店铺接入仍待验证；不要写成生产系统、自动退款或独立掌握全部代码。

## 一分钟讲解

“我从电商客服问题出发，把商品咨询、物流售后、退款投诉和其他问题分开处理。商品信息需要先查询，这里用两条明确标注的模拟资料；退款投诉交给人工，不能让模型承诺已经退款。另一个模块检索售后规则，返回 answer、source 和 need_human。曾出现回答有内容但 source 为空的问题，开发记录指出标题和正文被分开切块，修复思路是保留整条规则并传递标题。我用运行样例和源码核对已完成部分；两个模块还未验证串联，真实订单接入仍是下一阶段。”

## 可展示与可追问的内容

| 面试追问 | 展示或解释 |
| --- | --- |
| 分流怎么实现？ | 打开 graph.py，对应四条条件边；说明分类依赖模型，当前副本未包含分类节点 |
| 商品信息从哪里来？ | 打开 product_lookup_tool.py；执行本地检查，解释 TEST001 与未知编号的不同结果 |
| need_human 是否表示已派单？ | 只是输出标记；真实人工接管需要平台通道、任务记录和处理人验收 |
| 来源为空为什么不只改提示词？ | 若召回片段没有标题，下游无法可靠恢复；检查分块和上下文传递 |
| 已验收哪些，哪些待验证？ | 一条历史分流运行、三份完整单文件副本与本地商品工具；完整分支、规则回归及两模块集成待补 |
| 你本人做了什么？ | 按真实参与说明业务规则、平台操作、问题反馈与验收；区分 AI 生成、指导完成和独立排障 |

现场可在无云端环境下展示商品查询检查与历史证据。不要将离线模拟输出演示成实时模型或真实平台调用。
